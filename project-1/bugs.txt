1. Mis-spelling of "executable" in comment

Problem: The word "executable" is misspelled as "executible" in a comment.
Fix: Replace "executible" with proper spelling.


2. Missing header inclusions for various things

Problem: Some STL data types aren't explicitly included,
         which could be an issue on windows systems.
Fix: Add the necessary includes.


3. `exception` not passed by reference in catch statement

Problem: An exception is currently not caught by const reference.
Fix: Make it a const reference.


4. Missing read error handling

Problem: The program currently does not inform the user if
         `getline` encounters an error.
Fix: Check for read errors after using `getline` on `f`.


5. Unhandled parsing exceptions

Problem: When `stoi` is called, it has the potential to throw exceptions.
         These aren't properly handled at the moment.
Fix: Wrap `stoi` in a try-catch statement.


6. Accepting negative job IDs

Problem: Negative job IDs are currently allowed, which is unintuitive.
Fix: Error when reading a negative job ID.


7. `int` is not architecture independent

Problem: `int` isn't necessarily 32 bits all the time.
Fix: Change all integer types to their bit-specific
     equivalents (eg, `uint32_t`).


8. Unit test is done a little late in program execution.

Problem: `test_print_stats` is done midway through program execution.
Fix: Run the test at the start of the program.


9. Integer parsing is trash

Problem: If anything is trailing a numerical input, the program will
         silently proceed, even though it shouldn't.
Fix: Use `from_chars` instead of `stoi`.


10. Parsing fails if there is a trailing space

Problem: If a space is accidentially left at the end of a line in the file,
         parsing will fail it as an error.
Fix: Trim trailing whitespace before parsing.
